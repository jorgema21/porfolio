RESUMEN

Este porfolio es un proyecto en sí mismo. Desarrollé un entorno editorial propio diseñado desde cero para organizar mi trabajo en periodismo de datos, infografía y reportajes escritos bajo una lógica inspirada en los medios digitales. Haber trabajado en redacciones me llevó a plantear el porfolio como una portada periodística, donde los proyectos destacados aparecen jerarquizados visualmente y el resto se distribuye por secciones. Además, cada proyecto cuenta con una página propia para ampliar contexto, metodología y resultados. Esto incluye únicamente mi trabajo en el total del proyecto real.

El orden interno busca una gestión centralizada del contenido y un control directo sobre cómo construyo y presento cada pieza. Cada proyecto se compone de archivos locales que separan texto, imágenes y metadatos, lo que evita tener que reestructurar el código cada vez que añado un proyecto nuevo. Las rutas se generan de forma automática, por tanto, el porfolio crece sin obligarme a cambiar el código cada vez que incorporo nuevos contenidos.

Para el apartado visual, el código utiliza CSS nativo, variables personalizadas y componentes reutilizables. Los collages de las imágenes de portada usan fotografías con licencia Creative Commons. La jerarquía tipográfica, los colores y los elementos de interfaz se gestionan desde una única base común. Esto aporta coherencia visual y simplifica futuros cambios en el diseño. Elegí SvelteKit y Svelte 5 porque me permitían crear páginas estáticas veloces y flexibles, al mismo tiempo que me servían para ampliar mis conocimientos en estas herramientas de cara a futuros proyectos de datos.

El proyecto nace con soporte para dos idiomas, accesibilidad y una carga rápida de los recursos. La Inteligencia Artificial funcionó como un copiloto técnico durante el proceso para resolver dudas de aprendizaje, código, refactorización y traducción.

Más que una colección de trabajos, el propósito es disponer de un medio de publicación propio. Quise reunir diseño, periodismo, datos y desarrollo en un mismo entorno, capaz de mostrar mis reportajes y de sostener de forma directa su publicación y crecimiento futuro.

DESARROLLO (SI QUIERES SABER MÁS)

1. FILOSOFÍA DEL PROYECTO

Hace unos años usé y vi porfolios tradicionales basados en cuadrículas de proyectos y enlaces externos. Los trabajos aparecían como elementos aislados, sin contexto ni relación entre ellos.

Por ello decidí construir un entorno editorial propio inspirado en la lógica de los medios digitales. En lugar de presentar una simple colección de trabajos, quise crear un espacio donde cada proyecto tuviera una jerarquía, una narrativa y un papel dentro de un conjunto más amplio. La portada funciona como un primer plano y cada proyecto dispone de un espacio donde ampliar metodología, decisiones de diseño y proceso de trabajo.

Este enfoque elimina la dependencia de herramientas de terceros, pero también me exige asumir el control de todo el diseño. En esos servicios externos, el formato queda condicionado por plantillas predeterminadas. Aquí, en cambio, cada componente responde a necesidades concretas de cada proyecto.

Al mismo tiempo, el proyecto refleja mi propio proceso de aprendizaje. Meses antes existió una primera versión que nunca llegó a publicarse. El estudio de SvelteKit y Svelte 5 redefinió aquella idea inicial y me permitió construir un sitio mucho más flexible, escalable y veloz. En ese sentido, este porfolio muestra tanto proyectos terminados como la evolución técnica y profesional que hay detrás de ellos.

2. ARQUITECTURA DEL SISTEMA

En lugar de organizar el proyecto como un conjunto de páginas estáticas, el porfolio funciona como una publicación continua. Cada pieza no es una página aislada, sino parte de un archivo más amplio.

Cada proyecto combina tres elementos: contenido, metadatos y visualización. El contenido recoge la narrativa del trabajo, los metadatos organizan su clasificación y contexto, y la capa visual transforma esa información en una página navegable. La visualización nace de forma dinámica a partir de esta información. Gracias a esto puedo añadir nuevos proyectos sin tener que modificar gran parte del código.

Cada proyecto se construye a partir de archivos pensados como content.json y meta.json, que separan la información de la capa visual. Además, un archivo central de configuración agrupa los datos necesarios para la portada y la navegación global del sitio.

He elegido SvelteKit porque me permite tratar cada proyecto como una pieza independiente y así no tengo que escribir una y otra vez las rutas. La estructura interna de las carpetas no condiciona la navegación, que se resuelve sola a partir del contenido.

El resultado es un porfolio que crece sin alterar su base. Subir nuevos proyectos significa únicamente incorporar nuevos datos y no cambiar apenas el código. Con esto puedo seguir añadiendo textos e infografías para no tener que reorganizar todo.

3. HOME COMO SISTEMA EDITORIAL

La portada presenta un diseño editorial jerarquizado y huye de las listas convencionales de proyectos. Cada elemento tiene un peso visual específico dentro de una composición global que replica la primera página de un medio digital. Con esto guío la atención de los lectores según relevancia, actualidad e impacto visual, para no equiparar todos los trabajos.

Diseñé la home sobre una cuadrícula de doce columnas para distribuir las piezas con flexibilidad. Sobre esta base aplico distintas variantes de presentación como hero, feature, grid y list, que definen el nivel de importancia de cada proyecto dentro de la portada. Estas variaciones representan decisiones que tomo sobre qué elementos requieren protagonismo y cuáles actúan como acompañamiento.

La composición alterna piezas de gran protagonismo visual con grupos secundarios. Esta relación entre escala, densidad y ausencia de imagen define el ritmo de lectura de la portada. Así consigo emular el comportamiento de un periódico digital donde cada noticia posee un peso informativo diferente.

En los teléfonos móviles, todo pasa a una única columna fluida. Los proyectos visuales mantienen prioridad, mientras que los elementos más densos o de puro texto se desplazan hacia zonas inferiores.

4. PÁGINAS Y TIPOS DE CONTENIDO

Cada sección adapta su forma según el tipo de contenido y mantiene una lógica común de organización y lectura.

La sección de infografías concentra la mayor densidad de exploración. Su diseño facilita la navegación de datos y su visualización eficaz, por lo que combina treemap, buscador y filtros para descubrir relaciones entre proyectos. Cada pieza abre un contexto ampliado con sus metadatos y narrativa visual.

Otras páginas priorizan la lectura y el ritmo narrativo. En el caso de las secciones de estilo de vida y maternidad, presento todos los proyectos con un título y enlace a la web del periódico, y divido los trabajos por desplegables según el medio. Los textos e imágenes de cada pieza dentro de este porfolio los organizo en bloques para evitar la saturación visual y presentar un recorrido limpio. Con RichText puedo aplicar negrita o cursiva.

Las imágenes que componen los collages provienen siempre de fuentes con licencia Creative Commons. En mi porfolio anterior, la idea inicial era utilizar el mejor gráfico de cada proyecto como portada. Sin embargo, al considerar que no alcanzaban la calidad óptima, opté por diseñar una imagen personalizada para cada uno. En esta nueva versión he puesto mayor dedicación, he aplicado nuevas nociones de diseño y he consolidado una línea gráfica mucho más definida para los proyectos recientes.

Añadí un recurso interactivo común: el lightbox. Las imágenes no quedan fijas en la página, sino que sirven para ampliar información en detalle. Al hacer clic sobre una captura, el fondo se oscurece y el archivo gráfico destaca en primer plano. Esto permite observar las infografías a tamaño completo de manera cómoda.

La sección personal convierte datos biográficos en una narrativa navegable. Está pensada como un recorrido: una línea temporal en formato scrollytelling, habilidades técnicas organizadas como desplegables ordenados y una lectura visual de competencias lingüísticas.

El contacto reduce la interfaz a lo esencial. No hay capas innecesarias: solo una entrada directa a la comunicación profesional.

5. INTERNACIONALIZACIÓN

La internacionalización mediante i18n forma parte troncal de este porfolio desde su origen. Planteé el entorno para gestionar la parte escrita en dos idiomas mediante un archivo centralizado que simplifica el mantenimiento y evita duplicaciones.

La implementación se apoya en la reactividad de Svelte 5 mediante la runa $state. Esto asegura la actualización de los textos de forma inmediata.

El inglés utilizado busca reflejar el estilo del periodismo digital estadounidense bajo mi propio criterio y la asistencia de la IA, lejos de las traducciones literales. Busco seguir un enfoque propio de los medios norteamericanos, con elementos como la capitalización tipo headline case en los titulares y con punto al final de los subtítulos.

6. ACCESIBILIDAD Y EXPERIENCIA DE USUARIO

La accesibilidad forma parte de las condiciones iniciales de este porfolio. Busco una lectura cómoda en distintos contextos de atención y dispositivos para eliminar la fricción en los textos largos.

Combino las fuentes Epunda Slab y Nunito Sans para favorecer una lectura continua. Limito el ancho de línea con el fin de ayudar a la concentración y regulo la escala de las letras mediante valores fluidos con clamp(). Con estas decisiones mantengo la legibilidad y controlo el ritmo de la página.

Para el estilo utilizo un modelo de color moderno como OKLCH porque así controlo el brillo de los tonos de forma exacta. Diseño la paleta para asegurar un buen contraste en cualquier pantalla y cumplir con las pautas de WCAG 2.2.

El cuidado de la accesibilidad llega también a través de otros detalles de la web. El código respeta si una persona tiene activa la opción de prefers-reduced-motion en su ordenador y desactiva las animaciones por completo. Además, incluyo textos descriptivos en las imágenes mediante alt y en muchas ocasiones aria-label para que los reportajes funcionen bien en lectores de pantalla.

7. RENDIMIENTO Y DECISIONES TÉCNICAS

La velocidad de la web es una prioridad desde el primer día. Así, las imágenes grandes aparecen rápido y la navegación fluye en cualquier pantalla.

En el porfolio antiguo las imágenes estaban en formato JPG y pesaban demasiado. Para este proyecto he realizado una conversión manual a WebP con una calidad del 75% a través de Photoshop. Además, la compilación incluye el plugin ViteImageOptimizer para asegurar un peso mínimo automático en logotipos y recursos gráficos.

Incluso los archivos de las letras forman parte de este plan. Guardo las fuentes de forma local en formato .woff2, lo que elimina las llamadas a servicios externos como Google Fonts y asegura una carga estable. El porfolio se basa en un diseño estático para funcionar en GitHub Pages.

8. REFLEXIÓN FINAL

Este proyecto marca un punto de inflexión en mi forma de construir y entender un porfolio. Su estado actual representa el fruto de varios intentos previos, pruebas incompletas y decisiones que maduran con el tiempo.

Al comparar este trabajo con una versión anterior que quedó en un cajón, el cambio radical reside en el enfoque. El diseño previo acumulaba piezas aisladas, mientras que este proyecto nace para crecer, reorganizarse y sostener contenido de forma coherente.

La creación de este entorno consolida mi perfil de aprendizaje rápido y mi capacidad de esfuerzo. El desarrollo de este porfolio y mi ambición por hacerlo mejor y aprender me obligó a combinar diseño editorial, orden de archivos y contenidos, accesibilidad, traducción y desarrollo dentro de un mismo proyecto. Exploro herramientas vanguardistas y complejas que simplifiquen el desarrollo y generen un impacto visual potente. Mi propósito es elevar el nivel de calidad con cada gran proyecto.

La inteligencia artificial funciona como un copiloto técnico en fases clave como el orden de las carpetas, la traducción a inglés bajo supervisión y la iteración. Su uso optimiza mi flujo diario y aporta celeridad, por lo que actúa como una herramienta de apoyo en mi formación autodidacta.

Al final, este porfolio abre una metodología de trabajo a largo plazo. Consiste en una base preparada para evolucionar junto a mis futuras infografías y narrativas interactivas de periodismo de datos.
